# 读 PDF / 图片里的公式

**核心原则：不要只靠看图。** LaTeX 排版的 PDF 里，公式是**带坐标的真实文字**，不是图片。
先取文本层，再让公式 OCR 做交叉验证；两条通道一致才敢下结论。

工具在本技能目录下（见文末「本机路径」），记作 `$TOOL`；`$PY` 是带 pymupdf 的解释器。

## 1. 先判断这页公式是文字还是图片

```
$PY $TOOL paper.pdf --page 30 --probe
```

- 「数学字体占比高、图片 0 张」→ 走文本层（准、快、确定性）
- 「图片区域内没有文字」→ 公式是图片/扫描件，只能走图像通道

## 2. 文本层通道

```
$PY $TOOL paper.pdf --page 30 --scan            # 列出该页公式带
$PY $TOOL paper.pdf --page 30 --lines 2         # 取第 2 条并线性化
$PY $TOOL paper.pdf --page 30 --bbox x0,y0,x1,y1
```

上下标靠「字号变小 + 基线偏移」还原；大运算符靠 TeX 字体编码表还原。
输出是**近似 LaTeX**，用于阅读和比对，不保证可直接编译。

## 3. 图像通道

```
$PY $TOOL paper.pdf --page 30 --lines 2 --ocr --crosscheck
$PY $TOOL paper.pdf --page 30 --lines 2 --ocr --verify
```

- 渲染默认 **600 dpi**：实测 400 dpi 会把 `\mathcal{L}` 认成 `\angle`，600 dpi 才对。
- `--crosscheck`：拿文本层的字母 + 字体核对 OCR 输出，能定位到具体符号。
  文本层的字体名自带 LaTeX 语义（cmsy10 的 `L` 就是 `\mathcal{L}`）。
- `--verify`：换框、换分辨率再识别一次，不一致会明确告警。

## 4. 判定标准

- 两条通道给出同一个式子 → 可以引用
- 不一致 → `--render out.png` 裁出来自己看图定夺，或请用户确认
- **必须说明依据是哪条通道**，不要说"我读到了 X"却不给来源

## 5. 已知坑（都实测踩过）

1. **大运算符会退化成字母**：Σ 在 PDF 里是 `CMEX10` 的字符 `X`，直接复制文本会得到字母 X；
   做字母核对时要把 cmex10 排除，否则会误报。
2. **编码表必须按字体门禁**：不加判断，`I`(0x49) 会被译成 `∮`、`=`(0x3D) 会被译成 `⟩`，
   公式悄悄变错且不报错——最危险的失败模式。
3. **高括号被拆成三段**：一个 `[` 由「上/中/下」三个字形叠成，不折叠就输出 `[[[`。
4. **OCR 对裁切和分辨率敏感**：同一式换框，`\mathcal{L}` 会变成 `\angle` 或 `Z`。
5. **矩阵不能逐行框**：序列模型不懂"这是碎片"，会输出大段 `\mathrm{...}` 胡说。
6. **bbox 宁宽勿偏**：给偏了会读到相邻正文。
7. **结构性错误抓不到**：`\sum_{j=1}^{N}` 被认成 `\sum_{\cdot}^{N}` 时，字母核对会显示"一致"
   （因为字母都在），只有文本层能给出正确下标——所以两行输出必须对照着看。

## 6. 工具不在时

按这套思路重写，逻辑很短：

1. `page.get_text("rawdict", clip=rect)` 取字符，每字符有 `origin`（基线）与 `size`；
2. 以正文出现最多的基线为基准，字号 < 0.9em 且基线上移 → 上标、下移 → 下标；
3. 按 x 排序输出 `_{}` / `^{}`；
4. cmex10 编码表：0x58/0x50=Σ、0x52/0x5A=∫，**查表前先确认字体名含 CMEX**；
5. 同符号同 x、相邻 y 连续出现 → 折叠成一个。
